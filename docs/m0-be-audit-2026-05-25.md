### 2 — FE call to undefined BE path (1 case)

**`/api/writing/history` called by FE; BE has `/api/writing/history/{user_id}`**  
- File: `lib/api.ts:1422`  
- BE route: `GET /api/writing/history/{user_id}` in `app/routers/writing.py`  
- Impact: every call to `api.writing.history()` will 404. The FE comment explicitly acknowledges this: *"History endpoint may or may not exist on BE today — caller catches the 404 and renders empty state per V-013a.history follow-up plan."*  
- Fix: either add `GET /api/writing/history` (no param, reads from `user.id` in the auth dep) or update FE to call `/api/writing/history/{me.id}`.

---

### 3 — Auth-gate gaps on admin endpoints

`/api/admin/themes`, `/api/admin/topics` (GET), and `/api/admin/random-topic` have no authentication dependency. Any unauthenticated request can read the topic catalog and theme list. The other four admin endpoints correctly use `require_admin`. These three are low-risk (read-only, non-PII) but inconsistent with the rest of the admin surface.

---

### 4 — `/onboarding/*` prefix anomaly

The onboarding router mounts at `/onboarding` (no `/api/` prefix), which differs from every other router. This is intentional — the FE `lib/api.ts` correctly calls `/onboarding/questions` and `/onboarding/submit` — but is worth documenting so future router additions don't accidentally follow this pattern.

---

### 5 — Stubs that should be working (0 cases)

The only stub (`/api/stripe/webhook`) is intentionally partial and documented as a P-106 placeholder. No stubs exist that should already be production-complete.
